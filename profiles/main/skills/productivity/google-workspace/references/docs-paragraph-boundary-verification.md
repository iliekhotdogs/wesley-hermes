# Scoped Google Docs formatting: boundaries and verification

- Read the actual assignment/specification before applying remembered formatting defaults. Assignment-specific font, spacing, file-format and authorship requirements override course-wide conventions. If generative writing is prohibited except grammar checking, do not supply replacement reflection prose; restrict assistance accordingly.
- When deleting and reinserting complete paragraphs, inspect the following paragraph's text style: Google Docs can propagate the deleted paragraph's bold/underline styling onto a surviving blank paragraph. Restore only unintended inherited fields using a revision-protected request, then read back the exact target.
- Verify a narrow edit against a pre-edit snapshot. Content before the edit should compare exactly; content after a length-changing edit should compare after removing only positional startIndex/endIndex fields. Do not ignore style or text differences merely because positions shifted.
- Keep page boundaries and live edits intact. If a subsequent read differs outside the authorized region, inspect the precise difference rather than replaying the original mutation or overwriting concurrent user changes.
- Verify rendered pagination when promising that references occupy one page or the rubric remains separate. A temporary Drive PDF export plus PyMuPDF can inspect pagination without changing the remote document. Confirm local package availability; this environment's application venv may provide PyMuPDF when the default Python does not.
- For focused ad-hoc checks, use a temporary hermes-verify- script in the approved scratch directory, run it read-only against the live Doc, and remove it. An explicit `python -m unittest <temporary-module> -v` invocation provides recognizable test evidence; report it as an ad-hoc check, not a project-wide suite. Never rerun a document-mutating script merely to regenerate verification output.
