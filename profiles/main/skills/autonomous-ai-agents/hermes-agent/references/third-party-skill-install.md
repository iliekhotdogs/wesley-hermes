# Installing a third-party repository of skills

Use for a user-authorized repository install into the active profile, not an engine update.

1. Check current official Skills System docs and `hermes skills install --help`. Resolve `HERMES_HOME`; never install into another profile merely because it has a default skills directory.
2. Review the repository at an exact commit without executing upstream setup scripts. When a package/plugin manifest lists distributed skills, use that list rather than recursively installing internal, deprecated, miscellaneous, or in-progress directories. Include supporting files and the upstream license.
3. Compare candidate names with the active Hermes catalog. A raw recursive `SKILL.md` walk includes `.hub/quarantine` and can falsely report installed-name conflicts; prune hidden/cache paths or use the catalog.
4. Verify that `hermes skills inspect <identifier>` resolves to the requested source, not merely the same final skill slug. Repository-like identifiers can resolve to official skills sharing that slug. Do not install an unrelated result. Prefer an explicit supported pinned source. If the CLI cannot preserve provenance, inspect the live Hermes Hub API signatures before using its native bundle/quarantine/scan/install pipeline on a reviewed local clone.
5. For the native pipeline: construct `SkillBundle` with explicit name, full files, source, pinned identifier, trust_level='community', and commit/path metadata. Call `quarantine_bundle`, `scan_skill(path, source='community')`, `should_allow_install(result, force=False)`, then `install_from_quarantine` only if allowed. Never force a blocked verdict just to finish. Preserve nonconflicting existing skills. API names/signatures are version-dependent: confirm against the installed engine.
6. Translate foreign agent tool names with a clearly marked local compatibility note, rather than pretending those tools exist. Route subagent requests through standing specialist/isolation policy; use the profile scratch directory for temporary outputs. Do not treat foreign `disable-model-invocation` metadata as a Hermes enforcement control without verifying support. Installation is not execution authorization for tracker posts, project setup, infrastructure, or secret handling. Review shell templates but do not execute them during install.
7. Verify every installed member byte-for-byte against the intended adapted bundle, all manifest names against `_skill_catalog(skip_disabled=True)`, and all Hub registrations against intended install paths. Test `skill_view` on a representative skill and a supporting file. Report the actual installed count and exclusions. Do not claim functional end-to-end testing of external workflows when only installation/discovery was exercised.
8. Keep a manifest/provenance receipt outside temporary review files if updates need adaptation preservation. Do not blindly update locally adapted skills: repeat review and reapply intentional integration notes.

A source-update warning printed by the launcher is not permission to run `hermes update`; engine-pin/recovery policy still applies.
